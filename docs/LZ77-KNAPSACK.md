# Специфікація стиснення LZ77 та оптимізації пакування томів (`Lz77.cs`, `Knapsack.cs`)

## 1. Словникове стиснення з ковзним вікном (`LZ77`)

Алгоритм `LZ77` замінює повторювані фрагменти байтового потоку посиланнями на попередні входження у ковзному вікні пошуку.

### 1.1. Структура токена (`LzToken`)

Кожен елемент вихідного потоку кодується кортежем `(Offset, Length, NextByte)`:

* **`Offset` (`0..WindowSize`):** зміщення назад від поточної позиції до початку знайденого збігу у словнику. Якщо збігу не знайдено, `Offset = 0`.
* **`Length` (`0..MaxMatch`):** довжина знайденого збігу у байтах (за замовчуванням `MinMatch = 4`).
* **`NextByte` (`byte`):** перший символ після знайденого збігу, який гарантує просування вказівника вперед.

### 1.2. Стратегії розбору (`Greedy` vs `Lazy`)

* **Жадібний розбір (`CompressGreedy`):** на кожній позиції $i$ обирає найдовший доступний збіг у вікні пошуку та одразу фіксує токен, зсуваючи курсор на $\text{Length} + 1$.
* **Лінивий розбір (`CompressLazy`):** перед фіксацією збігу довжини $L$ на позиції $i$ перевіряє позицію $i + 1$. Якщо збіг у позиції $i + 1$ довший ($L_{\text{next}} > L + 1$), поточний байт виводиться як літерал (`Offset = 0, Length = 0`), а кодер переходить до довшого збігу на наступному кроці.

## 2. Оптимізація пакування томів (`0/1 Knapsack ДП`)

При розбитті архіву на томи обмеженого розміру $V_{\max}$ кожен підготовлений блок розглядається як неподільний предмет із вагою та цінністю.

### 2.1. Математична постановка

Для кожного кандидата `ArchiveBlock` визначаються:

* **Вага $w_i$:** розмір стиснутих даних плюс службовий заголовок запису:
  $$w_i = \text{CompressedData.Length} + 15$$
* **Цінність $v_i$:** пріоритет блока або виграш від його розміщення у поточному томі.
* **Обмеження місткості:** доступна корисна місткість тому $W = V_{\max} - 73$ (за вирахуванням 41 байта заголовка `Header` та 32 байтів підпису `HMAC-SHA256`).

### 2.2. Рекурентне співвідношення динамічного програмування (`SolveDp`)

Таблиця станів $dp[i][c]$ зберігає максимальну сумарну цінність підмножини з перших $i$ блоків при сумарній вазі не більше $c \in [0, W]$:

$$dp[i][c] = \begin{cases} dp[i-1][c], & \text{якщо } w_i > c \\ \max\big(dp[i-1][c],\; dp[i-1][c - w_i] + v_i\big), & \text{якщо } w_i \le c \end{cases}$$

Зворотний прохід по таблиці $dp$ відновлює точний набір індексів блоків, що максимізує заповнення тому без перевищення ліміту $V_{\max}$, усуваючи втрати простору, характерні для жадібного послідовного пакування.
